```
audioCapture
-> queue
    -> onsetDetector -> Judge
    -> DSP
```

현재 이런구조라고 생각이 된다.
그렇다면 onsetDetector -> Judge 이렇게 직렬로 연결되고 있는 부분이 문제가 되고 있는 것인가 의심된다.

onsetDetector는 Judge에게 넘겨 처리를 기다리는 동안에도 들어올 수 있는 입력에 대해 대응해야한다.

그래서 `aubio_onset_do()`가 필요했다.

하지만 chordTest로 확인된 것은 처리를 대기하는 동안 `aubio_onset_do()`을 사용하지 않는 것이 안정성을 늘려준다는 것이다.

onsetDetector -> Judge이 직렬이 병렬로 분리한다면 안정적이게 될까?

여기서 말하는 안정성은 사용자가 연주했을 때 의도한 타이밍에 전부 처리되는 것이다.
